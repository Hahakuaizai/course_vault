# 资料库（Course Vault）

把散落在桌面、下载文件夹和各种角落里的课程资料（实验报告、作业、课件、代码）集中登记到一个界面里：按目录多级归档、全库搜索、多格式直接预览、文本类文件还能内置编辑。

**核心原则：不动你的文件。** 默认只登记路径，原文件留在原处；需要时也可以把文件复制一份进软件保存（入库），原文件同样不受影响。

- 平台：Windows（Electron 桌面应用）
- 版本：1.0.118
- 许可证：MIT

---

## 快速开始

### 环境要求

- Node.js（建议 20 以上，数据层用到 Node 内置的 `node:sqlite`）
- npm

### 安装与启动

```bash
git clone https://github.com/Hahakuaizai/course_vault.git
cd course_vault
npm install
npm start
```

也可以：

- 双击 `启动.bat` —— 首次运行会自动 `npm install` 准备环境，之后直接启动
- `npm run dev` —— 以开发模式启动（带 `--dev` 标志）

### 打包免安装版

```bash
npm run build            # 默认输出到 E:\Apps\资料库
node build.js D:\任意目录  # 也可以指定输出目录
```

打包不依赖 electron-builder、不联网：直接复用 `node_modules/electron/dist` 里已下载的运行时，把 `electron.exe` 改名为「资料库.exe」并用 resedit 换上应用图标和版本信息，代码放进 `resources/app/`（特意不开 asar，否则应用内更新写不进文件）。

**产物体积**：zip 约 342MB，解压后 562MB。构成大致是 ——

| 内容 | 体积 |
|---|---|
| Electron 运行时（exe / dll / pak / icudtl） | ~330MB |
| `locales` 语言包 | 48.8MB |
| `resources/app`（代码 + 素材） | 205MB，其中素材 180MB |

`locales` 默认带五十多种语言，只留 `zh-CN.pak` 和 `en-US.pak` 能省掉约 45MB。素材是 webp / webm，已经压过一轮，再压只能省 15% 左右（alpha 通道压不动），不值得为它牺牲画质。

## 功能

### 多级目录

- 目录可以无限嵌套：课程、项目、收藏夹都行，目录可设置颜色
- 侧栏直接**拖拽**目录：拖到某个目录上 = 成为它的子目录；拖到空白 = 回到顶层；拖到行上/下缘 = 同级排序
- 右键/「更多」菜单同样可以新建子目录、重命名、改颜色、移到顶层、删除
- 删除目录会连同子目录一起移除（磁盘上的原文件不受影响）
- 同一层级下不允许重名，也不允许把目录拖进自己的子孙目录里
- 文件夹可以设置**封面图**，在卡片视图里一眼认出

### 导入文件

- 三种入口：文件选择器、整文件夹导入（递归扫描）、把文件**拖进来**或从资源管理器**复制粘贴**进来
- 导入文件夹时可选择**保留原来的文件夹结构**，自动建成对应的子目录树
- **两种保存方式**：
  - **链接**（默认）：只记路径，原文件一动不动
  - **入库**：复制一份进软件的数据目录，之后原文件删了也能看
- 文件卡片上带「入库」角标，右键可在两种方式之间随时互转
- 遇到重复文件会弹窗，让你当场选**跳过 / 替换 / 允许重复**
- 另有**重复文件扫描**：按内容找出库内的重复文件，勾选后批量清理

### 文件操作

- 多选、批量移动 / 复制到其他目录、批量删除
- 重命名、在文件夹中显示、用系统默认程序打开
- **指定程序打开 / 运行**：可为文件挑选编辑器或程序（自动识别已安装的 VS Code、Cursor、Notepad++ 等），也能记住选择
- 链接文件被移动或改名后会显示「已丢失」，可**重新定位**：手动选新位置，或让软件按文件名自动寻找

### 预览

| 格式 | 方式 |
|---|---|
| PDF | 内嵌渲染，可翻页缩放 |
| 图片 | 直接显示，网格里带缩略图 |
| 视频 / 音频 | 内嵌播放 |
| Word (.docx) | 解析为 HTML，表格和中文完整还原 |
| Excel (.xlsx) / CSV | 多工作表切换查看 |
| PPT (.pptx) | 按页提取文字（版式需用 Office/WPS 查看） |
| Markdown | 渲染 + 代码高亮 |
| 代码 / 纯文本 | 语法高亮（C/C++、Python、Java/Kotlin、Go、Rust、前端等） |

`.doc` / `.ppt` 等旧格式无法内嵌解析，会提示用系统程序打开。

### 内置编辑

- Markdown、代码、纯文本支持**内置编辑**：点铅笔图标进入，`Ctrl+S` 保存
- PNG / JPG / WebP 图片支持**内置编辑**：旋转、裁剪、画笔涂鸦、马赛克笔、橡皮擦，
  可撤销 / 重做，保存后直接写回原文件
- 保存前自动备份旧版本到「备份文件夹」
- Word / Excel / PPT 等复杂格式请用「用其他应用打开」，改完回到软件即可看到新内容

### 搜索

- **名称**：按文件名实时搜索
- **内容**：连文件正文一起搜（txt / md / 代码 / csv / json 等文本类），命中处会高亮片段
- 搜索始终在全库范围内进行，不受当前所在目录限制
- 可按类型筛选：文档 / 图片 / 音视频 / 代码 / 其他，或按具体格式（PDF、DOCX、Excel/CSV、PPT、TXT、Markdown）筛

### 回收站

- 删除目录或文件时弹窗选择：**放进回收站** / **彻底删除**
- 回收站按「删除批次」整条记录，可一次还原整批
- 入库文件的副本会被移到暂存区，还原时移回原处
- 支持单条彻底删除和清空回收站

### 主题与界面

- 明 / 暗双主题，陶土暖色调设计：暖纸白底 + 陶土橙强调色，标题衬线字体，低饱和细边框
- 主题切换带**圆形扩散揭幕动画**和整页动效（导航滑块指示器、卡片微交互、光线扫过效果）
- 设置里可开「减少动画」、可选择启动时是否打开上次的目录、卡片上是否显示文件大小

### 软件更新

- 应用可与一个**更新源目录**（如开发目录）按文件哈希比对，只同步有变化的代码文件，不碰用户数据和依赖
- 同步范围包含代码、样式、页面和桌宠素材（`.js` `.css` `.html` `.json` `.md` `.bat` `.ico` `.png` `.svg` `.webp` `.webm`）；桌宠的 225 张精灵图和 114 个动作动画都在其中
- 可设置自动比对间隔（每次启动 / 1h / 6h / 12h / 24h / 每天一次）；检测到更新后一键「应用并重启」
- 比对结果按**文件大小 + 修改时间**做了缓存，没变的文件不重复读取 —— `src/pets` 有 180MB 素材，全量哈希一轮 200ms 以上，走缓存后约 30ms
- **删除保护**：要删的文件如果带实际内容（有代码、有文本、素材超过 1KB）且占程序目录一半以上，判定为「开发目录选错了」并中止；删空文件、刚建的测试文件不拦
- 版本号用临时文件 + 改名的方式写入，中断不会留下半截 JSON
- 每次更新前的备份只保留最近 10 份

### 更新内容（自动生成）

- 每次更新后首次启动，自动把「这次到底改了什么」总结成更新说明，不需要人工写
- 做法：对比安装目录的文件指纹，对改动的文本文件做行级对比，从**新写的注释**里提炼目的 —— 注释块的**首行**当摘要，读不出关键词时退回代码改动统计
- 条目按 `修复` / `新增` / `改进` 分类，最多 8 条，末尾附改动文件列表
- 弹窗底部有**复制**按钮，把当前展示的内容整理成纯文本（版本、日期、条目、改动文件）
- 全部历史留在「设置 → 关于 → 更新内容」，只显示最近 10 次，更早的仍完整保存在数据里

### 项目架构图

- 「设置 → 关于 → 项目架构图 → 查看」在应用内**全屏展开**一张可交互的架构图
- 图是独立 HTML（`assets/架构图.html`），支持切换主题、缩放、导出图片、切换透视视图
- 用 iframe 内嵌而不是独立窗口：图有 800KB 和大量 SVG 动画，独立窗口的渲染进程会崩
- `src` 延迟到第一次打开才赋值，不拖慢启动；关闭只是隐藏，交互状态下次打开还在

### 发布助手（仅作者本机）

- 更新弹窗底部和设置里的历史视图都有「发布助手」按钮，点开是三段可一键复制的 PowerShell 代码
- **一、上传到 GitHub**：`git add / commit / push`，提交信息由本次更新说明简写而来
- **二、打包**：`build.js` 打包 → `ZipFile::CreateFromDirectory` 压成 zip → 删掉打包文件夹只留 zip。打包失败立刻中止，不会继续压一个不存在的目录
- **三、上传 Release**：`gh release create` 把 zip 传上去。这段是唯一联网的，断了只需重跑这段
- 门禁是数据目录里的 `plugin2-owner.marker`；发布版既没有标记，打包时也排除相关文件，界面上不会出现这个按钮

## 数据存放

| 内容 | 位置 |
|---|---|
| 索引数据库 | 应用数据目录（userData）下的 `vault.db`（SQLite） |
| 入库文件副本 | 默认在数据目录的 `files\` 下，**可在「设置 → 数据」改到其他盘** |
| 编辑备份 | 数据目录的 `backups\` |
| 数据库备份 | 数据目录的 `db-backup\` |
| 更新内容历史 | 数据目录的 `changelog\`（snapshot 指纹、prev 上一版文本、history.json） |
| 更新前备份 | 数据目录的 `update-backup\`，只保留最近 10 份 |
| 比对哈希缓存 | 数据目录的 `update-cache.json`，删了只是下次慢一点 |

- 索引数据已从早期的 JSON 迁移到 **SQLite**（Node 内置 `node:sqlite`，无外部数据库进程）：目录、文件、回收站、设置分表存储，每次保存是一个事务内的增量同步
- 内置**数据库健康检查与一键备份**，升级或改名导致数据目录变化时会自动迁移旧数据
- 入库位置支持迁移：在设置里点「更改」选新文件夹，会问你要不要连同已有文件一起搬过去
- 没有后端服务，关掉软件就什么都不跑

## 项目结构

```
course_vault/
├─ main.js              主进程：窗口、IPC、文件系统、更新调度
├─ preload.js           contextBridge 暴露给渲染进程的 vault API
├─ db.js                SQLite 数据层（dirs / files / trash / settings）
├─ updater.js           更新模块：与更新源目录按哈希比对同步代码
├─ build.js             免安装版打包脚本
├─ version.json         当前版本号
├─ 启动.bat              一键启动（首次自动装依赖）
├─ assets/              应用图标（ico / png / svg 多尺寸）、架构图.html
├─ .build-tools/        打包辅助工具（如 resedit）的独立依赖
├─ src/                 渲染进程
│  ├─ index.html        界面骨架
│  ├─ app.js            全部界面逻辑
│  ├─ changelog.js      更新内容自动生成（比对指纹 + 提炼注释）
│  ├─ styles.css        主样式（主题变量）
│  ├─ theme-switch.*    主题开关组件
│  ├─ theme-transition.css  主题切换揭幕动画
│  ├─ page-motion.*     页面动效层（导航指示器、卡片、光效）
│  ├─ folder-cover.*    文件夹封面（含主进程侧 folder-cover-main.js）
│  ├─ plugin2-main.js   发布助手门禁（仅本机，发布版不含）
│  └─ devtools.js       发布助手界面（仅本机，发布版不含）
└─ test/                验证脚本：单元测试 + 截图对比（node 直接运行）
```

架构要点：

- 渲染进程不直接碰文件系统，一切经 `preload.js` 的 `vault` API 走 IPC 到主进程
- 自定义 `vault://` 协议安全地把文件提供给渲染进程，只允许访问已登记的文件
- `updater.js`、`db.js` 都是可在纯 Node 里独立测试的模块，不必启动整个 Electron 才能验证

## 测试

`test/` 下是验证脚本（单元测试、数据库往返、更新逻辑、主题与截图对比等），用 Node 直接运行对应的 `.js` 文件即可，例如：

```bash
node test/unit-db-roundtrip.js
node test/unit-changelog.js
```

## 已知限制

- PPT 只能提取文字，看不到排版、图片、动画
- `.doc` / `.ppt` 旧格式不支持内嵌预览
- 超过 2MB 的文本文件不做内嵌预览
- 内容搜索只覆盖文本类文件（PDF / Word / PPT 内部文字暂不索引），单文件最多读 512KB
- 链接方式的记录是绝对路径，文件被移动或重命名后会显示「已丢失」（可重新定位，或改用入库方式）
